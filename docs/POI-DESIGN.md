# Utility POIs (phase B, part 1: data only)

`db/poi-wotlk335.lua` ships per-zone utility POI coordinates for the 3.3.5a
world, generated by `tools/gen_poi335.py` from the AzerothCore world database
(per-table base dumps in `azerothcore/azerothcore-wotlk`,
`data/sql/base/db_world`; the pinned commit is recorded in the generated
file's header):

| class    | source                                          |
|----------|-------------------------------------------------|
| `flight` | `creature_template.npcflag & 8192` (flight masters) |
| `mail`   | `gameobject_template.type = 19` (mailboxes)      |
| `inn`    | `creature_template.npcflag & 65536` (innkeepers) |
| `repair` | `creature_template.npcflag & 4096` (repair-capable vendors) |

Shape: `pfDB["poi-wotlk335"][class][zone] = { { xPct, yPct, name }, ... }` —
uniform 3-slot tuples, deliberately NOT the 4-slot units-coords shape (there
is no respawn slot; consumers must index exactly these three fields).

**Nothing consumes this table yet.** This is the data half of the pins work;
the consumer (map/compass pin layers fed from these classes) is phase B
part 2 and lands separately. Until then the file costs parse time only.

Method, validation results and per-class counts are documented in the
generated file's header and printed by every generator run: world→map-percent
via per-zone linear models fitted against pfQuest's own merged database (the
acfill335 method), rejected zones dropped rather than guessed, and every
emitted class cross-checked against pfQuest's own coordinates for the same
entities (median delta 0.00%, p90 0.10%, zero zone disagreements at
generation time).
